# なりすまし・送金詐欺対策コンサル — 実施カリキュラム

**位置づけ:** [収益ロードマップ.md](収益ロードマップ.md) ④の実務内容。SiteDoc AIの診断（SPF/DMARC未整備・類似ドメイン検出）を入口に提案する、非技術系の上位サービス。
**対象:** 送金権限者が少数に集中している中小企業・スタートアップ・ワンマン経営の会社（＝最も狙われやすい層）。

---

## なぜ今このサービスが必要か（提案時のトーク材料）

技術対策（SPF/DMARC設定、フィルタリング）だけでは防げない攻撃が増えている。理由は3つ。

1. **AIが「不自然な日本語」という従来の見破りポイントを消した。** 生成AIにより、フィッシング文面・音声・映像の精度が個人でも短時間で調達できるレベルに達している。
2. **攻撃は「なりすまし」ではなく「信用の偽造」を狙う。** 社長の声・映像を模倣し、「緊急」「極秘」「他言無用」で個別チャットに誘導し、心理的な密室状態を作ってから送金を指示する型が典型。
3. **正規ルートを経由した“逆手口”がある。** 社内の正式な申請フォームや承認フローの情報が漏れていると、そのルートを使った偽の指示は「正当な連絡だから」と信じられやすい。

→ **技術で作った穴は技術で塞げるが、「人が判断して送金する」という業務プロセスの穴は、ルールと訓練でしか塞げない。** これがこのサービスの存在理由。

## Part 1: 送金プロセスのルール整備支援

### Step 1. ヒアリングシート（現状把握）

初回訪問・オンライン面談で以下を確認する。回答を基に、次のルール設計を行う。

| 質問 | 確認したいこと |
|------|---------------|
| 送金を最終的に実行できる人は誰ですか？何人いますか？ | 権限の集中度（1人に集中＝ハイリスク） |
| 送金指示は誰から誰に、どの経路（メール／チャット／電話／対面）で来ますか？ | チャット・メール単独で完結していないか |
| 「いつもと違う」金額・振込先・急ぎの指示が来たとき、確認する手順は決まっていますか？ | 例外対応のルール有無 |
| 経営者・役員が出張中・不在のとき、送金判断は誰がどう代行しますか？ | 「今、社長は電話に出られない」を悪用されるスキ |
| 過去に「怪しい送金依頼」を受けたことはありますか？ | 実例があればルール設計の具体例に使える |

### Step 2. 二重承認ルールの設計テンプレート

顧客の実態に合わせて、以下をカスタマイズして文書化する。

```
【送金承認ルール（案）】

1. 金額基準
   - ◯◯万円以上の送金は、指示者本人へ「登録済みの電話番号」で
     必ずコールバック確認を行う（チャット・メール上の番号は使わない）。

2. 経路の原則
   - チャット・メール・SNSメッセージ「のみ」で完結する送金指示は、
     いかなる理由（緊急・極秘含む）でも実行しない。
   - 「他の人には言わないで」「電話ではなく、こちらで」という
     指示それ自体を、要注意サインとして扱う。

3. 承認者の分離
   - 送金の「依頼者」と「実行者」と「承認者」を最低3者に分離する。
     1人が3役を兼ねる状態を作らない。

4. 不在時のルール
   - 経営者・決裁者が不在の場合の「代行決裁フロー」を事前に定め、
     例外扱いで即実行しない。

5. 合言葉（コードワード）
   - 経営者・経理間で、電話やビデオ会議でも第三者が知り得ない
     合言葉を定期的に更新して共有する。
```

### Step 3. 納品物

- 上記をベースにした「送金承認ルール」文書（会社名・実態に合わせてカスタマイズ）
- 社内掲示・共有用の1枚サマリー（PDF/Word）
- 導入後1ヶ月のフォローアップ面談（ルールが実運用に乗っているか確認）

**単価目安:** ¥50,000〜／回（ヒアリング＋文書化＋導入フォロー1回を含む）

## Part 2: 社内教育・訓練メニュー

### A. 判断フローチャート（配布資料の骨子）

```
「送金・重要情報の提供を求めるメッセージ」を受け取ったら

  ① 「緊急」「極秘」「他言無用」のいずれかが含まれるか？
       YES → 要注意フラグ。②へ
       NO  → 通常確認へ

  ② チャット・メール・SNSだけで完結を求められているか？
       YES → 単独ルートでの実行は禁止。必ず③へ
       NO  → 通常確認へ

  ③ 登録済みの電話番号・対面など「別ルート」で本人確認できたか？
       YES → 承認ルールに従い複数人で承認 → 実行
       NO  → 実行しない。上長・経営者に即報告し、
              メッセージのスクリーンショットを保全する
```

### B. 30分レクチャー 台本（経理・経営者向け）

| 時間 | 内容 |
|------|------|
| 0–5分 | 導入：「なぜ今、この話をするのか」— AIによって“不自然な日本語”という防波堤が崩れたこと、海外で実際に数十億円規模の被害が出ている事例（ウェブ会議でCFOになりすましたケース等）を紹介 |
| 5–15分 | 手口の型を3パターン紹介：①ディープフェイク音声・映像による経営者なりすまし、②「緊急・極秘」で個別チャットに誘導する心理的密室化、③正規の申請ルートを装う“逆手口” |
| 15–22分 | 自社の「送金承認ルール」を読み合わせ、判断フローチャートを配布 |
| 22–28分 | ロールプレイ：講師が「社長」役でチャットメッセージ例を提示し、参加者に「あなたならどう対応するか」を答えてもらう |
| 28–30分 | まとめ：「騙されない」ではなく「騙されても被害を止める仕組み」が目的であることを強調 |

### C. ロールプレイ用サンプルメッセージ（配布・演習用）

実在企業を模倣せず、汎用的な例文として使用する。

> 「〇〇さん、今出張先で電話に出られないので、このチャットで対応してほしい。取引先への支払いが急ぎで必要になった。他の人には言わずに、以下の口座に◯◯万円を今日中に振り込んでおいて。詳細は後で説明する。」

→ 判断フローチャートの①②に該当することを参加者に気づかせる。

### D. 納品物

- 判断フローチャート（配布用A4 1枚、PDF）
- 30分レクチャー資料（スライドまたはWord）
- ロールプレイ用サンプル集
- 実施後の理解度確認クイズ（5問程度）

**単価目安:** ¥30,000〜／回（資料一式＋レクチャー実施）

## SiteDoc AI診断からの提案トーク例

診断結果でSPF/DMARC未整備・類似ドメイン検出があった顧客への提案文例。

> 「今回の診断で、メールのなりすまし対策（SPF/DMARC）が十分でないことが分かりました。これは設定を直せば技術的には防げますが、実は多くの被害は“設定より先に、担当者がチャットだけで送金してしまう”運用側の隙で起きています。技術面の改善に加えて、社内の送金ルールと判断フローを一緒に整備しませんか？」

**このセットが刺さる理由：** 診断結果という「客観的な根拠」があるため、コンサル提案が単なる営業トークではなく「診断の延長線上の当然の提案」として受け取られやすい。

## 注意事項（提供者としての倫理・法的な線引き）

- 本カリキュラムは**防御・予防のための一般的な業務プロセス設計**であり、特定の攻撃手法の実行方法や、AIの安全機構を回避する手口（いわゆるジェイルブレイク等）には一切触れない。
- 顧客への説明では「攻撃者の技術的手口の詳細」ではなく「組織としてどう備えるか」に焦点を当てる。恐怖を煽る営業ではなく、実務改善として提案する。
